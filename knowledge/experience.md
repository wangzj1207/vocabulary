## 2026-11-27：單字掌握狀態與錯題複習範圍

### 經驗

- 對靜態詞庫建立學習分類時，可沿用既有「已練習」及「錯題」集合，將新字、答對過、待複習狀態即時計算；避免重複保存可由舊資料推得的狀態，也降低既有 localStorage 遷移風險。
- 答對時應從待複習集合移除該詞；答錯時保留在集合中。單字本與練習頁共用狀態篩選函式，讓兩個入口對「待複習」的定義一致。
- 狀態計數用互斥分類呈現（待複習優先於一般已練習），同一詞條不會同時計入答對與待複習總數。

### 可複用範圍

- 適用於既有本機學習資料上新增篩選、摘要或錯題佇列的離線工具，可避免破壞舊版儲存鍵。
- 未來若要新增間隔複習，應新增每詞作答時間與複習到期資料，再以固定時間測試到期規則；不應把「曾答錯」直接等同於「永久待複習」。

### 本次應用

- 練習範圍和單字本新增答對過與錯題待複習篩選，單字本列出未練習、答對過或答錯待複習狀態及分類計數。
- 沿用 `wordGardenLearned` 與 `wordGardenMissed`，舊版資料可直接讀取；答對即解除錯題狀態，答錯則加入待複習。
- 新增純函式狀態計數與練習範圍測試，並補上單字本狀態篩選測試。
- 本次只完成即時錯題佇列，尚未實作依日期排程的間隔複習；排程前需先定義複習間隔與熟悉度規則。

## 2026-11-27：小螢幕觸控與鍵盤焦點

### 經驗

- 手機版把按鈕縮成圖示時，仍應保留足夠觸控高度；本專案將主要導覽、語音、篩選、分頁與跳過控制設為至少 44px。
- `outline` 不應只在滑鼠互動下隱藏；使用 `:focus-visible` 提供清楚的鍵盤焦點框，可同時涵蓋按鈕、選單與輸入欄位。
- CSS 靜態檢視能確認斷點和控制項尺寸規則，但不能代替瀏覽器目視驗收；若執行環境無法開啟本機頁面，應保留驗收待辦並說明限制。

### 可複用範圍

- 適用於純 HTML/CSS、響應式工具或遊戲的行動操作與鍵盤可見性改善。
- 44px 觸控高度是本專案採用的最低值；正式上線前仍應在真實手機與桌面瀏覽器檢查長文字、縮放和不同輸入方式。

### 本次應用

- 加入鍵盤焦點可見樣式，並提高手機版主要互動控制項的最小高度與語音按鈕尺寸。
- 瀏覽器環境拒絕 `file:` 本機頁面，因此只完成 CSS 靜態檢視；將目視驗收留在路線圖，不將其標成已完成。

## 2026-11-27：選擇題干擾釋義正規化

### 經驗

- 選擇題邏輯抽成純函式後，可使用固定隨機來源測試選項數、答案唯一性、詞性優先和候選不足時的回退，不必在瀏覽器手動重複出題。
- 以 Unicode 相容正規化、大小寫及標點移除去重，可排除只有空格或中英文標點不同的重複釋義；這只能做字面正規化，無法判斷真正同義或近義詞。
- Fisher–Yates 逐項交換比 `sort(() => Math.random() - 0.5)` 更適合作為可預期且不偏斜的陣列洗牌。

### 可複用範圍

- 適用於多選題、字彙測驗和小型題庫，尤其需要確保正解與干擾項互異並可重現測試的場景。
- 同義詞辨識需依賴可信的詞義分類或人工標註；單靠標點、空白正規化不應宣稱解決語意重複。

### 本次應用

- 新增 `quiz.js` 純函式，從同主要詞性的候選優先抽取不同釋義；不足三個時再由全庫補足。
- 選項依正規化後的釋義去重，並用 Fisher–Yates 隨機排列。
- 新增四項 JavaScript 測試覆蓋同義字面正規化、詞性優先、回退與洗牌。

## 2026-11-27：字庫 schema 與來源欄位稽核

### 經驗

- 不要只依賴計畫文件描述資料欄位；應直接讀取實際資料並比對欄位集合，再把文檔和自動檢查同步修正。
- 名為 `marked` 的布林欄位不能在沒有來源說明時推斷為「來源標記」或「人工校對」；欄位存在不代表來源、授權或品質已被確認。
- 每筆資料來源和資料集層級來源是不同粒度，若來源只能確認到整份匯入檔，應清楚記錄限制，而非複製一個未驗證的逐筆來源值。

### 可複用範圍

- 適用於靜態 JSON/JavaScript 資料集的 schema 文件、匯入流程與來源稽核。
- 更換或遷移詞庫前，可先加入 schema contract 測試，避免文件或程式長期依賴過時欄位假設。

### 本次應用

- 確認 5,624 筆資料都只有 `word`、`pos`、`meaning`、`marked` 四個欄位，且 `marked` 都是布林值；沒有逐筆 source 或 level 欄位。
- 修正路線圖對來源欄位的錯誤描述，並新增 CI schema contract 檢查。
- 不將來源、授權或 `marked` 語義標成已確認；待正式詞表和可再散布詞義來源確定後再補資料欄位。

## 2026-11-20：匯入雙語字表與干擾選項

### 經驗

- 遇到舊式字表時，不要假設英文詞性欄位一定有固定分隔符。部分來源會混用 `n./v.`、空格、大小寫或省略句點；可先用第一個中文字作為中文釋義起點，再正規化之前的詞性標記。
- 舊式字表可能使用 GBK 等非 UTF-8 編碼；解析後應明確寫成 UTF-8，並用實際中文字詞抽樣確認轉碼成功，不能只靠筆數驗證。
- 匯入時以正規化後的英文 headword 去重，缺少可辨識詞性的詞條可保留明確的「未標示」，不要因此丟失有中文釋義的詞條。
- 四選一題目的干擾選項應以「不同釋義」為單位去重，優先從相同主要詞性取材；同詞性候選不足時再退回完整字庫。這比直接從全庫隨機抽選更貼近詞性辨識練習。
- 把字典內容放進 DOM 時使用 `textContent` 或文字節點，避免把外部釋義字串當作 HTML。
- 為匯入資料加入不依賴外部套件的結構檢查，至少驗證筆數、headword 唯一性、必要欄位、中文釋義和解析殘渣。

### 可複用範圍

- 適用於其他採用舊編碼、詞性格式不一致的雙語字表匯入流程。
- 適用於多詞性字典的選擇題、拼字遊戲或詞性辨識題；新增來源時仍要人工確認詞義品質與資料授權。
- 資料結構檢查可套用到任何由靜態 JSON/JavaScript 載入的詞庫；若更換資料格式，應同步調整檢查器。

### 本次應用

- 重新解析字表，修正部分釋義前殘留的詞性片段，更新去重詞條數為 5,624。
- 題目優先使用相同主要詞性的干擾釋義，候選不足時回退到全庫；選項改用文字節點呈現。
- 新增 `tests/test_vocabulary_data.py`，檢查字庫基本格式與匯入品質。
- 本次品質修正不等於完成來源授權確認；授權未明的詞表不應只因為公開可下載就視為可再散布。
